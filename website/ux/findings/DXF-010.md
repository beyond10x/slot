# DXF-010: The search box takes the focus back from a keyboard reader who tabbed past it

- id: DXF-010
- title: The search box takes the focus back from a keyboard reader who tabbed past it
- class: affordance
- severity: S2
- metric: screen_only.keyboard_tabs
- status: open
- found_by: screen-only reader, two runs of one tree compared
- evidence_recording: none (static site)
- evidence_screenshot: none
- evidence_lines: focus put on the search box and moved to a navbar link at once: 439 ms later the box is a combobox and has the focus again. Tab counts of one tree at 1366x768, three runs: install 74, 75, 111; cancel 103, 97, 162; upgrade 82, 80, 117; plugin 41, 36, 45
- regression_asset: none

The search box loads its index when it first gets the focus (`loadIndex` in the search theme's `SearchBar`) and calls `input.focus()` when the index arrived.
A reader who pressed Tab in between is thrown back to the navbar and passes the same links again; how many depends on how fast the index loads, so the reader's Tab count differed from run to run by 1 to 5 on a slow reader and by 35 to 59 on a fast one.
The reader of `ux/bot.ts` now waits on the search box until its index is there and tabs on from it, so `screen_only.keyboard_tabs` is the count of a reader who is not thrown back, and the same in every run.
Open: the site still throws a real reader back. The fix is in the search theme (focus the box after the load only when it still has the focus) or a wrapper of it in the shared docs theme.
