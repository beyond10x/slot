# UXF-019: A build that failed a moment ago is not named on the first screen

- id: UXF-019
- title: A build that failed a moment ago is not named on the first screen
- class: cue
- severity: S2
- metric: screen_only.looks and screen_only.actions (busy-failed: 3 looks, 2 actions by pointer)
- status: closed
- found_by: heuristic review, R-11 (heuristic 1, one next thing)
- evidence_recording: none (hermetic replay busy-failed, states "loaded" and "build failed")
- evidence_screenshot: ux/rounds/R-11/shots/busy-failed@1366x768-build-failed.png
- evidence_lines: ux/rounds/R-11/shots/busy-failed@1366x768-loaded.png and -build-failed.png differ only in numbers (longest wait 41s to 44s, host CPU 60 to 65 %); the failed row is at page y 1614 of 2202 (ux/rounds/R-11/shots/review-full-busy-failed.png)
- regression_asset: ux/findings.spec.ts "UXF-019 busy-failed: the header counts the failed jobs of the last 60 min and opens the newest one" and "UXF-019 idle: no job failed, so the header shows no failed count"; ux/screen-only.spec.ts "screen-only busy-failed @ 1366x768 by pointer" (the job is in the first screen, one action)
- scenarios: 3 of 11 (busy-failed, pool-share, crowded)
- cost: S

The card says an agent's build failed a moment ago. When job 42 fails, nothing on the first screen
changes but live numbers: the header counts running, queued and waits, not failures, and the
timeline marks a failed bar with a 3 px red edge. The user has to know that failures are in the
Finished table, two screens down, and scroll there.

One-line fix: a header count such as "failed 1 (60 min)" that opens the newest failed job's output.

Fix (R-11): when a job failed in the last 60 minutes the header shows a button "failed N (60 min)" beside
the wait numbers of the same window; its accessible name ends "output of job N, the newest failed job"
and it opens that output. busy-failed: 1 look and 1 action by pointer (3 and 2 before).
