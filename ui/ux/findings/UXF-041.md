# UXF-041: Node cards count finished jobs over different windows

- id: UXF-041
- title: Node cards count finished jobs over different windows
- class: data
- severity: S2
- metric: none (the counts a reader compares)
- status: closed
- found_by: an independent review of the live view with a build node
- evidence_recording: none
- evidence_screenshot: none kept in the repository
- evidence_lines: the local card read `307 done · 185 failed`, build-1d `24 done · 10 failed`, while that day the node had finished 7,566 jobs and the local machine 2,052; the local card counted the jobs the daemon keeps, the node's card the last 30 its poll carries
- regression_asset: ux/findings.spec.ts "UXF-041 cluster-node-facts: each card counts its own node's finished jobs over the same windows" (and src/lib/cluster.test.ts "UXF-041: …")
- scenarios: cluster-node-facts: the node reports 1,700 jobs in the last 60 min and 7,566 today, and lists far fewer
- cost: M

Each card counted the finished jobs the page happened to list for its node. The local daemon
lists its last 500, a node's poll carries its last 30, so the card of the machine that did the
work looked idle.

Fix: every daemon counts the jobs it ended from its own job log, read once at start and kept up
as jobs end: the last 60 minutes and each clock hour of the last 25, by result (`ended_hour`,
`ended_hours`). A card shows `60 min N done, M failed · today N done, M failed`, today summed
from the reader's midnight, the same for every node. For a daemon that does not count, the card
counts the jobs the page lists.
