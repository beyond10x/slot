# UXF-050: A node job's id runs into the tool column

- id: UXF-050
- title: A node job's id runs into the tool column
- class: layout
- severity: S2
- metric: gates.problems (nodes-busy: the page scrolls sideways by 11 px, axe target-size on 68 job buttons)
- status: closed
- found_by: an independent review of the live view with a build node, jobs page at 1440 px
- evidence_recording: none (hermetic replay nodes-busy at 1366x768 and 1280x720)
- evidence_screenshot: none kept in the repository
- evidence_lines: the Running table printed `build-1d/7681` in a job column of 60 px, so the text ran over the tool name; with the node dropped from the cell a 7-digit id still did not fit, and nothing in the row said that the job ran on a build node
- regression_asset: ux/findings.spec.ts "UXF-050 nodes-busy @ 1366x768: a node job's id and its node stand in the job cell, clear of the tool cell" (and the same at 1280x720)
- scenarios: nodes-busy (ids of 7 digits, a node name of 16 characters, in Running, Queue and Finished)
- cost: S

The job column was sized for 6 digits, and a node job had no room for its node.

Fix: the job cell (`src/components/JobIdCell.vue`, used by the three job tables) holds the id and,
for a job of a build node, the node on a quiet 12 px line below it, cut with an ellipsis and named
in full in its hover text. The column is 80 px wide, enough for 7 digits in the harness's wide font;
the cell clips its content, so nothing reaches the tool column.
