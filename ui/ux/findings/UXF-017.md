# UXF-017: A pending upgrade that holds new jobs is not on the page

- id: UXF-017
- title: A pending upgrade that holds new jobs is not on the page
- class: missing state
- severity: S2
- metric: screen_only.failed
- status: closed
- found_by: screen-only bot, R-09 (new scenario upgrade-pending)
- evidence_recording: none (hermetic replay upgrade-pending)
- evidence_screenshot: rounds/R-09/shots
- evidence_lines: R-09 report, "upgrade-pending: no text "upgrade pending" on the page" at 1366x768 and 1280x720, pointer and keyboard
- regression_asset: ux/screen-only.spec.ts (scenario upgrade-pending in ux/scenarios.ts)

While a reload waits for the first moment no job runs, the daemon holds admission for up to
`--upgrade-hold`: builds queue although slots are free. `slot status` printed the reason; the web
view did not, because `State.upgrade` was never read and ticks did not carry it.

Fix: the tick carries `upgrade` (`#[serde(default)]`), the store takes it from the snapshot and
from every tick that has it, and the header shows the line as a status mark (`data-ux-region="upgrade"`).
