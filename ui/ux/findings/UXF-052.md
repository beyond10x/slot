# UXF-052: A job's session is a bare id or blank, and the cluster page names none

- id: UXF-052
- title: A job's session is a bare id or blank, and the cluster page names none
- class: copy
- severity: S3
- metric: none (session cells of the job tables and of the cluster page's job list)
- status: closed
- found_by: an independent review of the live view with a build node
- evidence_recording: none (hermetic replay nodes-busy and cluster-queue-empty at 1366x768)
- evidence_screenshot: none kept in the repository
- evidence_lines: the Session column showed 8 hex digits for every job and one blank cell; the page knew titles only from the census of the ticks it received, so a session that had stopped running processes before the page loaded kept its digits; the cluster page's job list had no session at all
- regression_asset: ux/findings.spec.ts "UXF-052 nodes-busy and cluster-queue-empty: a job's session is its title wherever the daemon knows one, and a job without one says so" and src/lib/host.test.ts "a job's session is its title, else its short id, else no session" (the test names it in quotes)
- scenarios: nodes-busy, cluster-queue-empty (one session titled only in `api/usage` grouped by session, one job without a session)
- cost: S

Fix: the page also reads the titles the daemon resolved for the sessions of the last 24 hours
(`api/usage?by=session`, on load and every 5 minutes); a census title stands. A job without a
session reads "no session" in the quiet colour, its hover text says it was started outside an agent
session. The cluster page's job list has a session column, kept in the stacked layout too.
