# UXF-038: A node's job is shown with a negative id

- id: UXF-038
- title: A node's job is shown with a negative id
- class: copy
- severity: S2
- metric: none (the id a reader sees)
- status: closed
- found_by: the operator, on the live view with a build node (39 rows with ids such as -1000000007499)
- evidence_recording: none
- evidence_screenshot: none kept in the repository
- evidence_lines: `/api/state` carried node jobs as `-(n + 1) * 10^12 - id`; the job tables printed `<node>/<id>`, the cluster view's job list, its queue chips, the output pane and every label and title printed the negative number
- regression_asset: ux/findings.spec.ts "UXF-038 busy-failed: a node's job shows the positive id its node gave it, beside a local job of the same id" (and the same for cluster-remote)
- scenarios: busy-failed and cluster-remote, each with a running and a finished job of node build-1d whose ids repeat a local job's
- cost: M

The daemon moved a node's job ids into a negative range so they could not meet a local id. An
earlier change (`<node>/<id>` in two tables) only rewrote the number in those two tables; every
other place still showed it, and `slot status` and the state API kept it.

Fix: the daemon keeps the id the node gave the job and marks the row `from_node`; the page names
a job by its node and id together (`jobKey`), so a node's job and a local job of the same id are
two rows; labels read `output of job 7089 on build-1d`; the output pane of a node's job says the
output stays on that node instead of asking this daemon for it.
