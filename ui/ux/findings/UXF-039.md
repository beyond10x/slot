# UXF-039: A running build node's lease ring reads 0:00

- id: UXF-039
- title: A running build node's lease ring reads 0:00
- class: data
- severity: S1
- metric: none (the time left a reader sees)
- status: closed
- found_by: an independent review of the live view with a build node
- evidence_recording: none
- evidence_screenshot: none kept in the repository
- evidence_lines: the card of node build-1d read `0:00 left of 1 h` while the node ran; the ring counted to the deadline of the daemon's cluster file, which was 4 hours past, while the node's own poweroff lay hours ahead
- regression_asset: ux/findings.spec.ts "UXF-039 cluster-node-facts: the lease ring counts to the poweroff the node reports, red while the cluster file says otherwise" (and src/lib/cluster.test.ts "UXF-039: …")
- scenarios: cluster-node-facts (`clusterNodeFacts` in ux/scenarios.ts): a node booted 12 h ago, a deadline 4 h past, a poweroff scheduled in 2 h
- cost: M

The lease ring knew one end time, the deadline of the cluster file on the endpoint. The node's
machine has its own: the poweroff systemd has scheduled. When the file was stale the ring showed
a running node as ended, and nothing said that the file and the node disagreed.

Fix: the node's daemon reads `/run/systemd/shutdown/scheduled` and its boot time and reports
both in its row (`poweroff_at`, `booted_at`). The ring counts from the boot to the poweroff the
node reports, and falls back to the file's deadline for a node daemon that reports none. When
the two lie more than 5 minutes apart, or a node reports its boot but no poweroff, the card
border and the ring turn red and the ring's caption says what the file says (`file 06:00`); the
full sentence is the caption's title and part of the card's label.
