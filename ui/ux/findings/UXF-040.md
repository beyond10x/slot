# UXF-040: Cloud cost stops at a stale deadline

- id: UXF-040
- title: Cloud cost stops at a stale deadline
- class: data
- severity: S1
- metric: none (the cost a reader sees)
- status: closed
- found_by: an independent review of the live view with a build node
- evidence_recording: none
- evidence_screenshot: none kept in the repository
- evidence_lines: the header read `cloud cost so far 5.50` while the node had run about 12 hours at 3.73 an hour (about 46); the count ran from the endpoint daemon's join to the deadline of the cluster file and stopped there
- regression_asset: ux/findings.spec.ts "UXF-040 cluster-node-facts: cloud cost counts from the node's boot, past the stale deadline" (and src/lib/cluster.test.ts "UXF-040: …")
- scenarios: cluster-node-facts
- cost: S

The cost started when this daemon first saw the node, not when the machine started, and ended at
the deadline even when the machine kept running.

Fix: the cost counts from the machine's boot as the node reports it (`booted_at`; its join for a
node daemon that predates it) to now, or to the node's leaving. A deadline no longer stops it.
