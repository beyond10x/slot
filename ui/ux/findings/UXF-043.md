# UXF-043: The local card reads CPU 0.0 on a busy host

- id: UXF-043
- title: The local card reads CPU 0.0 on a busy host
- class: data
- severity: S2
- metric: none (the load a reader sees)
- status: closed
- found_by: an independent review of the live view with a build node
- evidence_recording: none
- evidence_screenshot: none kept in the repository
- evidence_lines: the local card read `CPU 0.0 of 20` and `/api/state` `busy_cores` 0.0 while the host had a load of 5 to 7 and 1.8 to 4.1 cores in use by all programs; the card showed the pool's jobs only, and `busy_cores` is set only on the machine base
- regression_asset: ux/findings.spec.ts "UXF-043 cluster-node-facts: the local card shows the whole host's CPUs and load, not only the pool's" (and src/lib/cluster.test.ts "UXF-043: …")
- scenarios: cluster-node-facts: the pool's jobs use 0.0 CPUs, the whole host 4.1 with a load of 5.3
- cost: S

With builds on a node, the pool's own CPU is near 0, and the card said nothing of the programs
that load the workstation, the owner's sign that it is or is not blocked.

Fix: every daemon reports the CPUs busy on its whole machine (`host_cpu_milli`, from
`/proc/stat`) and its one-minute load (`load1`, from `/proc/loadavg`) in its node row;
`/api/state` adds `host_busy_cores` and `load1`. A card reads `whole host 4.1 of 20 CPUs · load
5.3`, its chart draws the whole host, and the pool's CPUs are in the label's title.
