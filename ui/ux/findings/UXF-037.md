# UXF-037: The machine's line charts and the running jobs come after the queue

- id: UXF-037
- title: The machine's line charts and the running jobs come after the queue
- class: layout
- severity: S2
- metric: none (order of the sections down the page)
- status: closed
- found_by: the operator, on the live view of a pool with 10 running and 70 queued jobs
- evidence_recording: none (hermetic replay busy-failed at 1366x768 and 1280x720)
- evidence_screenshot: none kept in the repository
- evidence_lines: the page read Queue, Running, Finished, then the host panel with the pressure and pool-size charts; with a long queue the charts and the running jobs were below the first screen
- regression_asset: ux/findings.spec.ts "UXF-037 busy-failed @ 1366x768: the machine charts come first, then Running, Queue and Finished" (and the same at 1280x720)
- scenarios: every scenario with jobs
- cost: S

With a long queue the reader saw who waits before what the machine does and what runs. The
order a reader asks in is: how loaded is the machine, what runs now, what waits, what ended.

One-line fix: one row of three line charts under the header, then Running, Queue, Finished.

Fix: `TrendCharts.vue` holds three charts of 80 px in one row (cores used on the whole machine,
pressure, pool size); the pressure and pool-size charts left the host panel. `App.vue` puts the
Running table before the Queue. The host chart by tool family, the Sessions table and the
timeline stay below the tables.
