# UXF-042: Failures are one count, whatever their cause

- id: UXF-042
- title: Failures are one count, whatever their cause
- class: data
- severity: S2
- metric: none (the counts a reader acts on)
- status: closed
- found_by: an independent review of the live view with a build node
- evidence_recording: none
- evidence_screenshot: none kept in the repository
- evidence_lines: the header read `failed 67 (60 min)` and the cards `185 failed`; a lost connection (exit 3), a command that was not found on a node (127) and a run-time limit (124) counted the same as a red test
- regression_asset: ux/findings.spec.ts "UXF-042 cluster-node-facts: failures are split by cause on the cards" and "UXF-042 busy-failed: the header splits the failed jobs by cause" (and src/lib/cluster.test.ts "UXF-042: …")
- scenarios: cluster-node-facts, busy-failed
- cost: S

A reader could not tell a build node's fault from a failing test: both were "failed".

Fix: a failure has one of three causes, by its exit: timeout (124, or ended at the run-time
limit), infra (3: a lost connection; 125 and 127: a command that could not run or was not
found) and test (any other). The daemon counts by cause (`Outcome::of`), the page the same way
for the jobs it lists (`outcomeOf`). The header reads `failed 67 (60 min) 60 test · 2 timeout ·
5 infra`, summed over every node's own count; a card shows the causes of its last 60 minutes
under its CPU chart.
