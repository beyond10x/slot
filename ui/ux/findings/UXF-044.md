# UXF-044: The output of a node's job is not shown

- id: UXF-044
- title: The output of a node's job is not shown
- class: data
- severity: S2
- metric: none (the output a reader opens)
- status: closed
- found_by: an independent review of the live view with a build node
- evidence_recording: none
- evidence_screenshot: none kept in the repository
- evidence_lines: the output pane of a node's job read "output not available", and the browser console had a 404 for `/api/jobs/<id>/output`; after UXF-038 the pane said the output stays on the node
- regression_asset: ux/findings.spec.ts "UXF-044 node-job-output: the output of a node's job is shown in the pane" (and src/lib/job.test.ts "UXF-044: …", crates/slot-cli/tests/remote_sync/node_view.rs)
- scenarios: node-job-output (`nodeJobOutput` in ux/scenarios.ts): busy-failed with a failed job of build-1d whose output the node keeps
- cost: M

The endpoint asked only its own daemon for a job's output; a node's job is kept on the node.

Fix: the page asks `api/jobs/<id>/output?node=<name>`. The endpoint reads the output from the
node over the channel it already polls the node with, the ssh forced command: the new read-only
`slot shell` step `slot output <id> [<from>]` prints the node daemon's
`GET /api/jobs/<id>/output-tail?from=<n>`, the kept chunks from chunk n on. The endpoint streams
them to the page as server-sent events and asks again every 2 s from the next chunk until the job
ended. A read that fails ends the stream with its reason.
