The table shows the rows in the order `api/usage` sends them and does not sort. The daemon sorts
by slot time, largest first, then by key (`crates/slot/src/usage.rs`), so a live page never shows
this order; the scenario's rows were written by hand in another one.

One-line fix: write the scenario's rows in the daemon's order and hold every scenario to it.

Fix (second polish pass after R-11): the rows of pool-share are in the daemon's order (36.5 %,
23.5 %, 23.3 %, 9.3 %, 7.5 %), and ux/scenarios.test.ts fails for a scenario whose usage rows are
not. The UI still does not sort: the order is the daemon's.
