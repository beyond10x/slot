# Story: the job list and job detail of a web UI generated from the ESS UI spec

## Outcome

The job list (running, queued and ended jobs, with a search and a state filter) and the job detail
of one job, with its live output, are pages of the Vue UI in `ui/` generated from an `ess-ui/1`
document in `spec/ui/`, bound to the daemon's HTTP surface as `spec/http.yaml` declares it. The
generator is slot's own (`b10x-slot-docs ui-pages`); it writes the pages into
`ui/src/generated/`, built from the hand-written components in `ui/src/components/`. The pages
stand at `#/jobs` and `#/jobs/<id>`; the dashboard without a hash is unchanged.

## Decision

D1 (operator, 2026-11-24 00:30 CET): the slot web UI is generated from the ESS UI spec.
Hand-written code goes only into declared host slots; the gate is `ess ui check --hosts` plus
regenerate-and-diff. The first story is job list and job detail. A gap of ESS goes to the ESS
repository as a story text; generated output is never patched by hand.

Addition (00:35 CET): every point where the generator gets in the way is a friction finding in
`docs/design/ess-ui-friction.md`; host slots stay small and declared.

Change of course (operator, about 00:45 CET): stop `ess generate ui --target react` at the first
friction that needs a change in ESS, log it, and build slot's own generator in Rust in
`crates/slot-docs` that targets the existing Vue app, with the looks of the current UI. That
stop is friction F5 (a job id drawn with the locale's grouping, `61,259`, with no option to
change it); the React output was not committed.

## Specification

Spec first: the specification is the source of truth, and the daemon serves what it declares.

- `spec/domains/pool.yaml`, domain `slot.pool`: the job as the daemon sends it
  (`crates/slot/src/types.rs` `Job`, field for field and with its JSON spellings), its lifecycle
  (queued, running, ok, failed, cancelled) and the views `slot.pool.Jobs` and
  `slot.pool.JobDetail`.
- `spec/http.yaml`: `GET /api/jobs` (the jobs of `/api/state`, active then ended, as a bare
  array) and `GET /api/jobs/{id}` (one job, 404 when the daemon holds none by that id).
- `spec/ui/slot.ui.yaml` (`ess-ui/1`) and `spec/ui/slot.hosts` (the host component names).

## Acceptance

1. `ess specify validate --path spec` and `ess specify http validate` against `spec/http.yaml`
   exit 0, with `slot.pool.Jobs` and `slot.pool.JobDetail` routed.
2. A daemon built from this change answers `GET /api/jobs` with every job of `GET /api/state`
   (`active` then `done`) as a JSON array, and `GET /api/jobs/{id}` with the one job or 404; a
   test in `crates/slot` asserts both, and an unknown id.
3. `ess ui check --path spec/ui/slot.ui.yaml --model spec --hosts spec/ui/slot.hosts` exits 0
   (`task ui-spec-check`), and its report lists every host slot with its reason and what it
   stands in for.
4. `b10x-slot-docs ui-pages` writes `ui/src/generated/pages/*.vue`, `pages.ts` and `ui.ts` from
   the document and the binding; `ui-pages --check` exits non-zero on a changed or a stale page,
   and refuses a key of the document it does not support by name. Both run in `task check`; CI
   installs the `ess` release `spec/ess-inputs.yaml` requires.
5. `ui/` typechecks and its tests pass with the generated pages; every host name of
   `spec/ui/slot.hosts` maps to a component in `ui/src/hosts.ts` (the typechecker refuses a
   missing one).
6. Screenshots of the job list and of one job's detail, served against the daemon's real JSON,
   are taken with Playwright.
7. `docs/design/ess-ui-friction.md` lists each friction finding, `docs/design/ess-ui-gaps.md`
   holds the story text of every gap for the ESS repository; no generated file is edited.

## Out of scope

The other views of the UI (usage, census, cache, settings, charts), a link to `#/jobs` from the
dashboard's header, and the UX gates' scenarios for the new pages are later stories.
